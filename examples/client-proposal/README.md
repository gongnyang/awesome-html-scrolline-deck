# 온결 리테일 고객 제안

매장 대기 경험 개선을 위한 90일 파일럿 제안 웹덱입니다. 브랜드·사례·관측 수치·목표치는 모두 설계 시나리오이며, 실제 사업 실적이나 성과를 의미하지 않습니다.

## 장면 흐름

| # | scene id | 장면 템플릿 | 실제 제목과 발표 역할 |
|---:|---|---|---|
| 1 | `01-hero` | `frame-scrub-hero` | **고객은 계산 전에 떠난다** — 가상 피크 시간 문제와 제안을 시네마틱 이미지로 엽니다. |
| 2 | `02-challenge` | `question-reveal` | **문의 대기와 계산 대기가 한 줄에 겹칩니다** — 합성 관찰 질문을 열고 두 대기 지점의 관계를 보입니다. |
| 3 | `03-evidence` | `annotated-chart` | **대기는 점심 피크에 쌓인다** — 가상 6일·420건 시나리오의 시간대별 중앙값과 13–14시 피크를 읽습니다. |
| 4 | `04-journey` | `step-flow` | **대기는 고객 여정의 세 지점에서 쌓입니다** — 탐색 → 상담 → 결제에서 대기가 겹치는 위치를 따라갑니다. |
| 5 | `05-solution` | `system-map` | **POS는 그대로, 대기부터 안내까지 한 흐름으로** — 모바일 대기표·상담 슬롯·직원 알림의 운영 관계를 설명합니다. |
| 6 | `06-pilot` | `timeline-roadmap` | **3개 점포에서 12주 운영 가설을 검증합니다** — 2주 기준 측정·8주 적용·2주 평가의 기간 비율과 산출물을 제시합니다. |
| 7 | `07-impact` | `before-after` | **대기 중앙값 8.4분 → 5분 이하** — 가상 기준선과 검증 전 목표치를 같은 척도에서 구분합니다. |
| 8 | `08-options` | `option-matrix` | **첫 검증은 표준안으로 세 점포에서 시작합니다** — 라이트·표준·확장안을 공통 기준으로 비교하고 추천 이유를 설명합니다. |
| 9 | `09-governance` | `system-map` | **개인정보 없이 흐름만 집계** — 관찰 → 익명화 → 집계 데이터의 경계와 흐름을 보여 줍니다. |
| 10 | `10-close` | `agenda-path` | **세 점포 파일럿의 기준선을 합의합시다** — 대상 점포·성공 지표·운영 책임자 합의를 요청합니다. |

각 장면에는 발표자 노트가 포함됩니다. 실행 중 `N` 키로 노트를 열고, 화살표 키나 스페이스로 이동하며, `F`로 전체 화면을 전환합니다.

## 실행

```sh
cd examples/client-proposal
pnpm install
pnpm run dev
```

## 근거와 한계

브랜드, 대기 관측값, 고객 이탈 수치, 파일럿 일정과 성공 목표는 모두 가상 사례입니다. 8.4분은 합성 시나리오의 기준선이고 5분 이하는 검증 전 목표치입니다. 목표치는 성과 예측이나 보증으로 해석하면 안 됩니다. 개인정보 관련 장면도 실제 배포 설계나 법률 자문을 대신하지 않습니다.
